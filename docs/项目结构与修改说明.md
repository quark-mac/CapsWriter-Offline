# 项目结构与修改说明

> 记录本项目在官方 CapsWriter-Offline 基础上经过二次开发后的结构，以及开发过程中遇到和处理的特殊情况。阅读本文可快速了解当前项目的组成与设计取舍。

## 一、修改后的项目构造

### 核心组件（官方原有）

| 组件 | 说明 |
|---|---|
| `start_server.exe` | 服务端，内置 Python 3.13 运行时（`internal/`），负责语音识别 |
| `start_client.exe` | 客户端，同样内置运行时，负责录音、快捷键、输出 |
| `internal/` | PyInstaller 打包的内置 Python 环境（`python313.dll` + 标准库 + 第三方库），**主程序完全自包含，不依赖系统 Python** |
| `core/` | 主程序源码（服务端、客户端、UI、工具） |
| `config_client.py` / `config_server.py` | 客户端/服务端配置文件（Python 源码形式） |

### 新增组件（本次开发）

| 组件 | 说明 |
|---|---|
| `settings/` | 设置工具包（仅依赖标准库），含 6 个文件 |
| `start_config.py` | 设置界面源码入口 |
| `start_config.exe` | 打包后的设置界面（自包含，不依赖系统 Python） |
| `start_caps.exe` | 打包后的无感启动器（启动服务端+客户端，自包含） |
| `启动CapsWriter.pyw` / `启动CapsWriter.vbs` | 启动脚本（源码运行方式） |

`settings/` 内部文件：

| 文件 | 作用 |
|---|---|
| `gui.py` | tkinter 设置窗口：开机自启动 / 桌面快捷方式 / 客户端设置 / 服务端设置 四个页 |
| `config_editor.py` | 用 AST 精确读写配置文件，只改目标行、保留注释 |
| `autostart.py` | 注册表开机自启动管理（`HKCU\...\Run`），含换路径自动修复 |
| `shortcut.py` | 桌面快捷方式创建/删除/更新（调用 PowerShell COM） |
| `manage_shortcut.ps1` | 快捷方式底层操作脚本（纯 ASCII，兼容 PowerShell 5.1） |

### 修改的核心源码

- `core/ui/tray.py` — 启动时**强制隐藏**控制台窗口（原 `toggle_window` 在窗口已隐藏时会 `SW_RESTORE` 又显示出来）
- `core/client/app.py` / `core/server/app.py` — 启动时自动修复开机自启动路径
- `core/client/manager/tray_manager.py` / `core/server/ui/tray_manager.py` — 托盘菜单加入「⚙️ 设置」入口
- `config_server.py` — `enable_tray` 默认 `False`（服务端默认不显示托盘，避免与客户端重复）

## 二、新增功能说明

### 1. 图形化设置界面
- 托盘菜单「⚙️ 设置」，或在独立进程运行 `start_config.exe` 打开
- 四个页：**开机自启动**、**桌面快捷方式**、**客户端设置**、**服务端设置**
- 配置编辑通过 AST 改写 `config_client.py` / `config_server.py`，保存前自动备份 `.bak`，写回后校验语法

### 2. 无感启动
- `start_caps.exe` 用「创建独立控制台但隐藏窗口」方式启动两个 exe，控制台从创建起即不可见，无闪烁
- 配合托盘启动时「强制隐藏」，避免窗口被 `SW_RESTORE` 恢复显示
- 注意：`taskkill`、PowerShell 等命令行调用必须加 `CREATE_NO_WINDOW`，否则会弹出控制台

### 3. 开机自启动与桌面快捷方式的自动修复
- 自启动命令走 `wscript.exe + 启动CapsWriter.vbs`（`wscript` 路径固定，不依赖 Python），以隐藏窗口方式启动
- 桌面快捷方式指向自包含 exe（`start_caps.exe` / `start_config.exe`）
- 程序启动时自动检测注册表自启动项与桌面快捷方式，若指向的不是当前目录（软件换路径/换位置），自动更新为当前目录

## 三、特殊情况说明

### 1. 两个代码基线不同（重要）
本机存在**两个代码目录，不是同一套基线**：
- **运行目录** `...\CapsWriter-Offline\CapsWriter-Offline`：从 release 解压的**较旧版本** + 本项目的设置功能，是实际使用的软件
- **Git 仓库**（fork 的本地克隆）：上游 **main 分支（更新，含黑名单等新功能）** + 本项目提交的设置功能

提交到 GitHub 时只把改动的文件同步到 main 基础上，因此两者基座不同。这是有意保持的现状。

### 2. 内置 Python 与系统 Python
- 主程序（exe）使用 `internal/` 内置的 Python 3.13，**不依赖系统 Python**
- 设置界面与启动器原本依赖系统 Python（`pythonw.exe`），已通过打包为 exe（`start_config.exe` / `start_caps.exe`）实现自包含
- 两个 exe 必须放在**项目根目录**（与 `config_client.py` 同目录），因为运行时以「exe 所在目录」定位配置文件

### 3. exe 不入 Git 仓库
- 上游 `.gitignore` 明确排除 `*.exe`（构建产物惯例）
- `start_config.exe` / `start_caps.exe` 是本地构建产物，**不提交到 GitHub**
- 重新打包命令（PyInstaller 需先安装）：
  ```bash
  python -m PyInstaller --onefile --windowed --name start_config --paths . start_config.py
  python -m PyInstaller --onefile --windowed --name start_caps --paths . 启动CapsWriter.pyw
  ```

### 4. 服务端托盘默认隐藏
- `config_server.py` 中 `enable_tray = False`，服务端不再显示托盘图标，只保留客户端一个
- 需要时可在设置界面「服务端设置 → 启用托盘」改回并重启生效
